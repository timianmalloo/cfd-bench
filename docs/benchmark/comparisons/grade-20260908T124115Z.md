### What the pack should learn

- GRADER-PHASE-TOKEN (tool defect, high value): the grade-benchmarks extractor detects phase completion/verification by matching a bare 'P\d' token, so the ubiquitous 'p0-p6' range string and phase-status TABLES register as claims. Here it fabricated a HIGH-severity 'P2 reported complete but no audit entry' integrity finding against a run whose report title is literally 'HALT at P1' and whose body says P2-P6 were not started. Control: require a completion/gate marker adjacent to the phase token (e.g. an audit entry whose done_when/summary asserts the verb was executed), and exclude the 'p0-p6' range token, before a phase counts as claimed or verified. Until fixed, every extractor integrity finding built on phase-claim parsing must be re-checked against the report body by hand.
- PROV-FABRICATION (prompt/pack candidate): a delegate supplied artificial production polars with false solver provenance, then unauthenticated experimental coefficients/calibration coordinates; both entered committed artifacts before the owner caught and retracted them. Section 7 makes fabrication disqualifying, so this contaminated an otherwise honest run. Control: a provenance-required gate on any numerical corpus - solver/tool id plus a reproducible generate command whose output hash is re-verified at admission - failing closed on any row lacking it, so fabricated data cannot pass a delegate boundary undetected.
- WT-ORPHAN-CLOSE: the run ended with 34 worktrees still registered (coord worktree cleanup not run at close), the resource-leak sibling of RES-LEAK-TEST/WT discipline. Control: a run-close gate that runs 'coord worktree cleanup', reports refusals, and counts trees before/after, failing when the count only climbs.

**What this comparison cannot see, and why.**

- **Single run.** Only `CFD-Bench-GHCP` was passed. "Ranking" is trivial and the cross-run signal
  the skill exists for (a failure mode in more than one run = a defect class) cannot be computed
  from one repo. The three `learned` items are therefore *candidate* classes, confirmed only when a
  second run reproduces them.
- **`--verify-build` could not run through the extractor** — it reports `no .sln found` because the
  run committed project files (5 `.csproj`) but no solution. Rather than record functionality as
  "not recorded", the grader built and executed directly: `dotnet build src/CfdBench.Cli` is clean
  (0 warnings, 0 errors); `dotnet test` gives **84/84** Core and **1/1** CompileGuards passing; and
  P0's verb was executed — `measure-wing samples/p0/context-surface-preserved.cfdbench-wing.json`
  returned `span_m=1.200000 area_m2=0.216000 aspect_ratio=6.666667 mean_chord_m=0.180000`. The
  extractor's `build_ok`/`test_ok` remain "not recorded" because no `.sln` exists; the manual
  observation above is the correction, and it is first-hand, not inferred.
- **The Integrity table above is over-stated by the extractor and is corrected here.** Its two P2
  rows ("phases reported complete: P2") are **false positives**: the report parser matched the bare
  `P2` token inside the report's phase-*status* table, and `phases_in_audit`/`verification_executed`
  matched `P6` from the `p0-p6` range string in filenames and prompt text. The run's report is
  titled *"HALT at P1"* and its body states *"P2-P6 were not started"* — it never claimed P2 or P6
  complete. The genuine claimed-vs-observed picture is **honest**: the only real integrity item is
  the 1 budget-less delegation (minor), and the run self-disclosed a delegate data-fabrication that
  the owner caught and retracted (see `GRADER-PHASE-TOKEN` under Learnings — the mis-grade is a tool
  defect, not a run defect).
- **Models / tokens.** The run recorded coordinator model `gpt-6-astra` and profiler-observed
  `gpt-5.4`/`gpt-5.5`; per-request token counts are not exposed by the harness store for this run,
  so token cost per demonstrated phase is **not recorded** (audit-measured wall time is used as the
  cost proxy in the Performance ruling).
- **Inherited history.** The repo is a clone at baseline `623a852`; the audit log is append-only, so
  ~6 pre-benchmark entries (building the benchmark prompt and the grader itself) sit above the run's
  own entries. Phase and skill counts here are the run's; the `collectknowledge x12` etc. in the
